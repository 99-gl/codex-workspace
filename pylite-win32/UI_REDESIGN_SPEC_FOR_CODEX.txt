PyLite 原生 Win32 界面改版规范（供 Linux 端 Codex 实现）
=========================================================

文档状态：用户已确认
基线分支：fix/windows-startup-manifest
基线提交：9aed82f
目标风格：Typora + Codex 风格的克制浅色桌面编辑器


一、任务目标
------------

在不更换技术栈、不牺牲窗口拖动和调整尺寸流畅度的前提下，重新设计 PyLite 的
视觉层。当前程序的功能和三栏布局基本正确，但直接暴露了传统 Win32 默认控件：
凸起灰色按钮、传统菜单栏、硬边框、过小的界面字体、粗重代码字体和缺少留白的
内容排版，使界面看起来像旧式系统工具。

本次只做视觉、排版和必要的轻量交互改造，不扩展编辑器业务功能。

最终视觉应满足：

- 简洁、现代、克制，不使用渐变和厚重阴影；
- 编辑器是视觉中心，文件树和辅助栏退居次要层级；
- 保留原生 Windows 窗口框架，窗口拖动应和当前修复版一样流畅；
- 在 100%、125%、150% DPI 下比例协调、文字清晰；
- 继续生成原生单文件 PyLite.exe。


二、绝对约束
------------

1. 继续使用原生 C++ Win32。
2. 不引入 Qt、WebView2、Electron、WPF、WinUI、MAUI、浏览器渲染层或其他大型 UI
   运行时。
3. 保留 WS_OVERLAPPEDWINDOW 和 Windows 原生非客户区：标题栏、最小化、最大化、
   关闭按钮以及系统阴影全部由 Windows 管理。
4. 不实现无边框窗口或自绘窗口按钮；不要重新引入窗口拖动延迟。
5. 不使用 WS_EX_COMPOSITED 包裹主窗口或整个界面。
6. 不在 WM_PAINT 中创建大量临时 GDI 对象；字体、画刷和画笔需要缓存，并在 DPI
   改变或程序退出时统一重建/销毁。
7. 不用固定像素直接完成全部布局。以下尺寸均以 96 DPI 为基准，必须通过 DPI
   缩放函数换算。
8. 必须保留已经修复的 DPI manifest，不得恢复旧的
   dpiAware=PerMonitorV2 错误写法。
9. 不改变现有文件打开、保存、补全、Python 运行、三栏分隔条和输出区分隔条功能。
10. 不覆盖已经验证可启动的候选版本；新的 EXE 应以独立候选版本交付。


三、整体视觉方向
----------------

关键词：安静、轻量、留白适度、低对比边框、少量深色强调。

不要使用：

- 系统默认凸起按钮；
- 3D 凹陷边框；
- 大面积中灰色背景；
- 渐变、发光、厚阴影；
- 多种不一致的圆角；
- 默认粗体代码；
- 为了“现代”而加入过度动画。

建议颜色常量集中到 Theme/UiMetrics 结构，不要将 RGB 值散落在消息处理函数中。

基础颜色（浅色主题）：

  AppBackground       #F6F7F9
  PanelBackground     #FFFFFF
  EditorBackground    #FFFFFF
  OutputBackground    #FBFCFE
  Border              #E4E7EB
  Divider             #E1E4E8
  TextPrimary         #24262B
  TextSecondary       #747A84
  TextMuted           #9AA0A8
  HoverBackground     #EEF0F3
  SelectedBackground  #E8EDF7
  SelectedText        #26344D
  PrimaryButton       #292B30
  PrimaryButtonHover  #3A3D43
  PrimaryButtonText   #FFFFFF
  Success             #24945E
  Error               #C43C3C
  FocusAccent         #5576C7

边框一律尽量使用 1 个逻辑像素；面板圆角统一为 6 个逻辑像素，按钮圆角统一为
5 个逻辑像素。不要给最外层 Windows 窗口增加自绘圆角。


四、目标布局
------------

  ┌────────────── Windows 原生标题栏 ──────────────┐
  ├ 文件  编辑  运行  工具       保存  Python 3.13  ▶运行 ┤
  ├──────────┬──────────────────────┬───────────┤
  │ 文件列表  │                      │  辅助面板  │
  │ 230 px   │       代码编辑区       │  260 px   │
  │          │                      │           │
  │          ├──────────────────────┤           │
  │          │   可调高度的输出区域    │           │
  ├──────────┴──────────────────────┴───────────┤
  │ 状态                            Ln / Col / UTF-8 │
  └─────────────────────────────────────────────┘

96 DPI 下建议尺寸：

  顶部命令栏高度       46 px
  状态栏高度           24 px
  左栏默认宽度        230 px
  右栏默认宽度        260 px
  左右栏最小宽度      160 px
  中央编辑区最小宽度  400 px
  输出区默认高度      180 px
  输出区最小高度       90 px
  分隔条视觉宽度        1 px
  分隔条可命中宽度      5 px
  普通面板内边距        8 px

保留左/中/右宽度和输出区高度的拖动调整及持久化。窗口变窄时优先压缩左右栏到最小
宽度，不能让编辑器宽度变成负值或让控件相互覆盖。


五、原生标题栏
--------------

1. 保留 Windows 原生标题栏及窗口控制按钮。
2. 标题格式维持“文件名 — PyLite”，例如“hello.py — PyLite”。
3. 未保存时可显示“hello.py * — PyLite”或一个星号，但不要加入复杂标签栏。
4. 使用现有 PyLite 品牌图标；如果图标在小尺寸下模糊，应重新导出包含
   16/20/24/32/48/256 像素层级的 ICO。
5. 不强制标题居中，因为这会要求接管非客户区，违背流畅性约束。


六、顶部命令栏
--------------

移除传统 HMENU 在客户区形成的旧式菜单视觉，改成一个高度 46 px 的轻量命令栏。
弹出菜单仍可使用 TrackPopupMenuEx，以保留成熟的原生菜单行为。

左侧菜单：

  文件   编辑   运行   工具

- 使用 Segoe UI/微软雅黑 UI 系列常规字重；
- 96 DPI 下约 13 px；
- 单项左右内边距 10 px；
- Hover 时显示 HoverBackground；
- 保留原有菜单内容、快捷键和命令 ID；
- Alt/F10 及键盘操作不得明显退化。

右侧操作按以下顺序排列：

1. 保存：32x32 的透明图标按钮；未修改时可降低图标对比度。
2. Python 解释器：约 136x32 的浅灰胶囊选择器，显示
   “绿色状态点 + Python 3.13 + 下拉箭头”。
3. 运行：约 78x32 的深灰主按钮，文字为“▶ 运行”。

命令栏左右外边距 12 px，控件之间间距 8 px。命令栏背景使用 PanelBackground，
底部绘制一条 Border 色分隔线。按钮只需要 Normal、Hover、Pressed、Disabled 四种
状态，不增加动画。

优先实现方式：

- 命令栏使用独立子窗口负责背景和菜单文本绘制；
- 保存、解释器、运行可以使用 BS_OWNERDRAW 子按钮，以保留焦点和键盘行为；
- 图标可以使用 Windows 10/11 都存在的 Segoe MDL2 Assets，并提供文字或简单 GDI
  线条图标回退；
- 不要为了几个图标引入完整图形框架。


七、中央编辑区域
----------------

1. 去掉 RichEdit 的 WS_EX_CLIENTEDGE 以及传统凹陷边框。
2. 中央编辑卡片使用白色背景、1 px 弱边框、6 px 圆角。
3. RichEdit 放在卡片内部，左右内边距约 14 px，顶部内边距约 12 px。
4. 编辑区域尽可能占满中央可用空间，不能增加类似网页正文的大块外围留白。
5. 保留水平和垂直滚动能力；第一版继续使用系统滚动条，禁止为美化滚动条引入
   重型自绘。
6. 当前行可使用极浅的灰蓝色背景，但不得导致每次按键都重绘整个编辑器。
7. 焦点状态只需轻微改变卡片边框颜色，不使用发光效果。

增加行号栏：

- 宽度约 46 px；
- 背景可使用 #FAFBFC；
- 行号右对齐，字体与代码字体一致但字号小 1 px；
- 普通行号使用 TextMuted，当前行号使用 TextSecondary；
- 只绘制当前可见行，不要遍历整个文档；
- 可使用 EM_GETFIRSTVISIBLELINE、EM_LINEINDEX、EM_POSFROMCHAR 等 RichEdit 消息
  计算可见行位置；
- 编辑、滚动、缩放和窗口调整时只重绘行号栏及必要区域；
- 不开启自动换行时实现最清晰；如现有编辑器允许换行，需要正确处理显示行与逻辑
  行，不能让行号重复或错位。


八、代码字体和语法配色
----------------------

字体优先级：

  Cascadia Mono -> Consolas -> 系统等宽字体

96 DPI 默认参数：

  字号        15 px 左右
  字重        400 / FW_NORMAL
  行高        22 px 左右
  Tab 宽度    4 个空格

当前截图中的代码字体明显过粗。语法高亮刷新时应先保证基础字符格式为正常字重，
不要因为高亮逻辑残留 CFE_BOLD。只有真正需要强调的 UI 标题可使用中等字重，代码
本身不使用粗体强调。

建议语法颜色：

  普通文字    #24292F
  关键字      #8250DF
  字符串      #B42318
  函数/调用   #0969DA
  注释        #6E7781
  数字        #0550AE
  装饰器      #953800
  当前行背景  #F7F9FC

语法高亮时应尽可能保存并恢复选择区与滚动位置，不产生明显闪烁，也不要因为视觉改版
增加高亮定时器的全量刷新频率。


九、左侧文件列表
----------------

1. 默认宽度 230 px，继续允许拖动调整。
2. 面板背景为 PanelBackground，与编辑器之间只用一条 Divider 分隔。
3. 顶部标题区高度约 38 px，左侧显示“资源管理器”，右侧放打开文件夹图标按钮。
4. 移除当前单独的灰色“打开文件夹”凸起按钮。
5. 文件和文件夹行高约 28 px，左右内边距 8 px。
6. 文件夹、Python 文件使用克制的单色图标；图标与文字间距约 6 px。
7. 当前文件使用 SelectedBackground 和 4 px 圆角选中底色。
8. Hover 使用 HoverBackground。
9. 弱化或移除传统 TreeView 树形虚线，使用缩进和展开箭头表达层级。
10. 文本使用 UI 常规字重，文件名不应粗体。

可以尝试 SetWindowTheme(tree, L"Explorer", nullptr) 获得较现代的基础行为，再通过
NM_CUSTOMDRAW 控制行色和选中状态。如果使用 SetWindowTheme，需要增加系统 uxtheme
链接或安全地动态加载，不引入第三方 DLL。


十、右侧辅助栏
--------------

1. 默认宽度 260 px，继续允许拖动调整。
2. 顶部标题区与左栏保持相同高度、字体和边距。
3. 标题暂定“辅助面板”或“检查器”；本次优先使用“辅助面板”。
4. 内容未实现时不要显示醒目的“内容待定”。
5. 空状态可以在面板中上部显示非常淡的图标和“暂无内容”，也可以只保留空白。
6. 不加入没有实际功能的按钮、卡片或说明文字。
7. 右栏必须保留稳定布局，方便后续放置代码结构、变量或运行信息。


十一、输出区域
--------------

1. 输出区仍位于中央编辑器下方，默认高度约 180 px。
2. 保留顶部横向分隔条和拖动调整高度功能。
3. 输出标题栏高度约 34 px，背景为 PanelBackground，底部或顶部使用 1 px 弱边框。
4. 左侧显示“输出”和运行状态点。
5. 右侧“清空”“折叠”改为透明图标按钮，Hover 时出现浅灰底色。
6. 输出正文背景为 OutputBackground，去掉 WS_EX_CLIENTEDGE。
7. 输出字体使用 Cascadia Mono/Consolas，约 13～14 px，正常字重。
8. stdout 使用主文字色；stderr 使用 Error；过程状态使用 TextSecondary。
9. 将旧式文本：

     [进程结束，退出码 0]

   显示为：

     ● 已完成 · 退出码 0

   成功状态点使用 Success，非零退出码使用 Error。
10. 折叠后只保留标题栏；再次点击恢复上一次高度。


十二、底部状态栏
----------------

不要继续使用当前带明显分区边框的传统 STATUSCLASSNAME 默认外观。可以改成一个
轻量自绘状态栏子窗口。

96 DPI 下高度 24 px：

- 左侧：就绪、正在运行、运行成功或运行失败；
- 右侧：Ln 10, Col 38   UTF-8   Python；
- 背景使用 PanelBackground；
- 顶部使用 1 px Border；
- 字体约 12 px，颜色为 TextSecondary；
- 各字段之间使用留白，不绘制凸起分区框。


十三、字体规范
--------------

UI 字体优先级：

  Segoe UI Variable（存在时）
  Segoe UI
  Microsoft YaHei UI（中文回退）

代码字体优先级：

  Cascadia Mono
  Consolas

不要假设 Windows 10 一定安装 Cascadia Mono；必须实现回退。字体高度应根据当前 DPI
通过 MulDiv 或统一 Scale 函数计算。WM_DPICHANGED 后重建字体并重新布局。


十四、绘制和性能要求
--------------------

1. 使用 DeferWindowPos/BeginDeferWindowPos/EndDeferWindowPos 批量更新子窗口位置。
2. 调整主窗口尺寸时不要销毁和重建编辑器、TreeView 或输出控件。
3. 拖动分隔条时使用 SetCapture，只更新相关尺寸，并尽量只失效分隔条和发生变化的
   面板区域。
4. 自绘命令栏、状态栏、标题区可以各自使用小范围内存 DC 双缓冲；禁止给主窗口加
   全窗口双缓冲或 WS_EX_COMPOSITED。
5. 自绘窗口只有在完整覆盖背景时才处理 WM_ERASEBKGND，避免错误返回导致残影。
6. 画刷、画笔、字体、图标缓存到界面资源对象，不能每次 WM_PAINT 都创建。
7. 现有 350 ms 定时器不得用来无条件 InvalidateRect 整个主窗口。
8. 调整窗口、移动窗口和拖动分隔条时不执行语法全量重算、文件树扫描或 Python
   补全查询。
9. 不增加持续动画、阴影动画或淡入淡出。
10. 关闭程序后必须释放所有自建 GDI 对象；用调试计数或 GDI 对象数量检查是否泄漏。


十五、实现建议
--------------

建议拆分出最少量的可维护结构，而不是继续把所有绘制代码塞进主窗口过程：

  Theme/UiMetrics
    颜色、逻辑尺寸、DPI 缩放、字体和 GDI 资源

  CommandBar
    菜单文本、保存、解释器和运行按钮的绘制与命中测试

  PanelHeader
    左栏、右栏和输出区共用的标题视觉

  StatusBar
    自绘底部状态信息

  EditorGutter
    可见行号绘制

可以仍然保存在少量 .cpp/.hpp 文件中，不要求引入复杂组件框架。公共颜色和尺寸必须
集中管理，避免每个窗口过程使用一套不同的常量。

弹出菜单、文件对话框、解释器选择对话框继续使用系统原生控件，不需要全部重写。


十六、功能与交互不得退化
--------------------------

改版后必须保留并验证：

- 新建、打开、保存、另存为；
- 未保存修改提示；
- 文件夹树懒加载；
- Python 语法高亮；
- Tab/Enter 接受补全，方向键选择，Esc 关闭；
- import json 后 json. 的动态补全；
- Python 解释器自动检测和手动选择；
- F5 运行，Shift+F5 停止；
- 实时 stdout/stderr 和退出码；
- 左/右栏宽度调整；
- 输出区高度调整与折叠；
- 布局持久化；
- .py/.pyw 打开方式注册；
- PyLite.exe file.py 命令行打开文件；
- 原有 Ctrl 快捷键和菜单命令。


十七、验收标准
--------------

视觉验收：

1. 不再出现灰色凸起的默认按钮。
2. 编辑区、左右栏和输出区层次清楚，但没有厚边框。
3. 代码字体为正常字重，行距舒适。
4. 顶部操作紧凑且右对齐，保存为图标，解释器像轻量选择器，运行为深色主按钮。
5. 左侧文件树具有现代选中态，不再像系统示例控件。
6. 右侧空面板不显示“内容待定”等临时开发文字。
7. 最大化到 2560x1440 左右时，编辑区仍占据绝大多数空间，不出现人为的大块外边距。

尺寸/DPI 验收：

1. 在 1920x1080 的 100%、125%、150% 缩放下分别检查。
2. 文字不裁切，按钮不重叠，分隔条可命中。
3. 中英文文件名和菜单均清晰。
4. 最大化、还原、最小化后布局正确。

性能验收：

1. 快速拖动原生标题栏时与当前 9aed82f 基线一样流畅。
2. 连续拖动窗口边缘调整尺寸时无明显延迟、闪烁或残影。
3. 连续拖动左右分隔条和输出分隔条时无明显卡顿。
4. 空闲状态不持续占用 CPU。
5. 视觉改版不应显著增加内存占用；只增加少量 GDI 资源和图标是允许的。

功能验收：

1. 打开 hello.py，编辑、保存和 F5 运行正常。
2. 输出成功信息显示正确。
3. 补全和语法高亮没有因自绘界面失效。
4. 关闭窗口后无崩溃，事件查看器没有新的 PyLite Application Error。
5. 连续启动和关闭 5 次。


十八、交付要求
--------------

请在独立实现分支提交：

1. 所有源码和资源修改；
2. 构建脚本与必要的结构/回归测试更新；
3. 新的候选 PyLite.exe；
4. 新 EXE 的文件大小和 SHA-256；
5. 修改文件清单；
6. 哪些项目已在 Linux 完成，哪些仍需 Windows 真机验证；
7. 如果没有 Wine 或 Windows GUI 环境，必须明确说明未做真实界面验证。

建议候选名称包含版本或 redesign 标记，不要直接覆盖已经验证能启动的基线 EXE。
不要在没有 Windows 实测的情况下声称视觉、拖动流畅度和全部功能已经通过。


十九、实现优先顺序
------------------

第一阶段（必须）：

- 统一主题、字体、背景和弱边框；
- 顶部命令栏与现代按钮；
- 去掉 RichEdit/输出框的凹陷边框；
- 左右栏标题和文件树选中态；
- 输出标题栏和状态栏；
