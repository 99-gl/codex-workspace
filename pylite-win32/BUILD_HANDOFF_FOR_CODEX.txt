PyLite Win32 界面改版：Linux 构建交接
====================================

你的职责是构建和报告，不要自行重新设计或大范围修改源码。

目标分支：implement/win32-ui-refresh

请执行：

1. 拉取并切换到 implement/win32-ui-refresh。
2. 确认工作区没有混入其他分支的未提交文件。
3. 使用项目原有 GCC 13 MinGW-w64 POSIX 工具链运行：

     cd pylite-win32
     ./scripts/build-win-x64.sh

4. 如果编译失败：
   - 保存完整编译输出；
   - 提交一份 BUILD_RESULT.txt，写清第一个真实编译错误及后续错误；
   - 不要凭猜测大改 UI 源码；
   - 将日志提交并推送到当前分支，交回 Windows 端修复。

5. 如果编译成功：
   - 确认核心测试、结构测试和 manifest 校验全部通过；
   - 确认结果是 PE32+、Windows GUI、x86-64；
   - 输出 EXE 文件大小和 SHA-256；
   - 将新候选保存在 pylite-win32/PyLite.exe；
   - 更新 BUILD_RESULT.txt，列出工具链版本、测试结果、大小和 SHA-256；
   - 提交 PyLite.exe 与 BUILD_RESULT.txt 并推送当前分支。

6. 不要创建或覆盖正式 Release。该 EXE 仍需 Windows 10 真机验证。


本次源码改动概览
----------------

- 保留 Windows 原生标题栏和 WS_OVERLAPPEDWINDOW；
- 移除附着在窗口上的传统菜单栏，使用客户区命令栏和 TrackPopupMenuEx；
- 保存、解释器、运行、打开文件夹、清空、折叠改为 BS_OWNERDRAW；
- 加入集中式浅色主题和 DPI 缩放资源；
- TreeView 使用 Explorer 主题、28 px 行高、系统文件图标和现代选中颜色；
- 正文编辑器由 RichEdit + 独立 PyLiteGutter 迁移为静态集成的 Scintilla 5.6.6；
- Python 高亮改用静态集成的 Lexilla 5.5.3 Python lexer；
- 行号、正文、选区和滚动条由同一个 Scintilla 控件同步绘制；
- 输出区和状态栏改为轻量自绘；
- 布局使用 DeferWindowPos；
- 没有使用 WS_EX_COMPOSITED；
- 删除 RichEdit 正文区的定时正则全文重着色和独立行号栏刷新路径；
- 补全列表改用 Scintilla 原生自动补全窗口，保留原来的静态和 Python 模块动态补全来源；
- 移除编辑器上重复的 Tab 子类拦截，候选确认完全交给 Scintilla 原生按键路径，避免补全后再插入一个制表符；
- 动态属性补全会在输入点号后的前缀时持续生效，例如 collections.de 仍使用 collections 的属性候选并定位到 deque，而不会退回 def/del 等静态候选；
- 构建新增 Scintilla/Lexilla 源码静态编译及系统 uxtheme、imm32、oleaut32 链接；
- 修正 RichEdit 行距参数：1.4 倍行距使用 rule 5 + dyLineSpacing=28；
- 编辑区滚动不再依赖异步 InvalidateRect 刷新行号，也不在滚动期间运行正则全文高亮。
- 新增 problems/0300-longest-increasing-subsequence ACM 题目目录，包含题面、空白提交代码和 10 组测试；
- 右侧待定区域改为原生 RichEdit 轻量 Markdown 题面，不引入 WebView2；
- 底栏新增输入/输出标签，自定义输入通过匿名管道送入 solution.py 的 stdin；
- 顶部新增“测试”按钮，运行同目录 test_solution.py，并保留进程树停止能力；
- 新增 Ctrl+F5 运行测试，F5 仍运行当前代码，Shift+F5 停止；
- 题库扩展到 41 道：新增 40 道 ACM 格式题目、40 个空白 solution.py 和共 396 组固化测试；
- 所有新增题面均不包含来源和进阶段落，链表、二叉树与多答案题明确了本地序列化及排序规则；


需要特别核对的编译点
--------------------

- src/ui_theme.hpp 中 EnumFontFamiliesExW 的回调类型；
- uxtheme.h 与 -luxtheme；
- vendor/scintilla 与 vendor/lexilla 的 C++17 静态编译；
- Scintilla DirectWrite 后端需要的 imm32、ole32、oleaut32、uuid 和 advapi32；
- CreatePythonLexer 返回的 ILexer5 交由 SCI_SETILEXER 管理；
- RichEdit PARAFORMAT2 / PFM_LINESPACING；
- NMTVCUSTOMDRAW、TVN_DELETEITEMW 和系统 HIMAGELIST；
- WM_DPICHANGED 在 _WIN32_WINNT=0x0601 编译目标下的头文件可用性；
- std::initializer_list 中的 GDI 句柄类型推导。

Windows 端已使用旧 GCC 8.1 做过尽力的语法检查。新增 UI 层没有暴露语法错误；
本机检查仍会因旧 libstdc++ 不支持本项目既有的 std::filesystem/wstring 和
std::regex::multiline 而失败，因此必须以服务器上的 GCC 13 构建结果为准。


Windows 真机后续验证项
----------------------

- 启动后至少保持运行 10 秒；
- 快速拖动窗口是否保持流畅；
- 最大化、还原和连续调整窗口尺寸；
- 拖动左栏、右栏和输出区分隔条；
- 100%、125%、150% DPI；
- 文件菜单、编辑菜单、运行菜单、工具菜单；
- 保存、选择解释器、运行和停止按钮；
- 文件树展开、打开文件和系统图标；
- 行号随编辑、滚动和光标移动同步；
- 高亮、Tab 补全和模块动态补全；
- 输入 coll 后按 Tab，应得到 collections 且光标紧跟单词末尾，不得额外缩进；
- import collections 后输入 collections.de，候选应继续包含并定位到 deque/defaultdict，不得切换成 def/del/delattr；
- stdout/stderr、退出码、折叠和清空；
- 打开 problems/0300-longest-increasing-subsequence/solution.py 后右侧显示题面；
- 在输入标签填入样例，F5 应把内容传给 solution.py；
- Ctrl+F5 应输出 10 组测试结果，空白 solution.py 初始应判定失败；
- 左侧 problems 根目录应显示 41 个题目目录，随机抽查数组、链表、二叉树和动态规划题均能加载题面；
- 新增题目的空白 solution.py 运行测试应失败，填写正确解答后应按各题固定顺序通过；
- .py 打开方式和命令行打开文件。
